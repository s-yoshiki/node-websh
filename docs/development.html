Development

A pnpm workspace driven by Turborepo. Node.js 20+ and pnpm 11+.

Setup

git clone https://github.com/s-yoshiki/node-websh.git
cd node-websh
pnpm install

node-pty ships prebuilt binaries for common platforms, so there is normally nothing to compile.

About the postinstall step

node-pty execs a small spawn-helper binary to start the shell, and the executable bit on it does not survive extraction in every package manager and CI setup. When it is missing, every spawn fails with a bare posix_spawnp failed and no hint that the cause is a file mode. scripts/postinstall.mjs restores it.

The dev loop

pnpm dev

Two processes: the Hono server on :8999 and Vite on :5173. Work against http://localhost:5173 — Vite proxies /api and /ws to the backend, and the server runs with --allowed-origin http://localhost:5173 so the origin check accepts it.

The server prints its access token on startup. The printed sign-in link points at :8999; when working through Vite, paste the token into the login form on :5173 instead.

Against the built output

pnpm build
pnpm start

This exercises the real path: one process on :8999 serving both the API and the built frontend, with no Vite in the way.

Checks

Command What it does
pnpm lint Biome, formatting and lint rules together
pnpm lint:fix Applies what Biome can fix automatically
pnpm typecheck tsc --noEmit per package
pnpm test Unit tests through the Node test runner, including ones that spawn a real PTY and assert on what the shell sees
pnpm test:e2e Starts the built server and drives sign-in, the origin check, the WebSocket close codes and a real shell command
pnpm build Frontend, then the server bundle that serves it

Shared configuration

TypeScript and Biome settings live in configs/ as workspace packages rather than being copied per app. 

configs/tsconfig/base.json        strict defaults, no DOM
configs/tsconfig/node.json        + Node types
configs/tsconfig/react-lib.json   + DOM and JSX
configs/tsconfig/react-app.json   + Vite client types
configs/biome/base.json           formatter and lint rules

A package opts in by extending it:

{ "extends": "@node-websh/tsconfig/react-app.json", "include": ["src"] }
Two things to know

The shared Biome config is base.json, not biome.json, on purpose: Biome auto-discovers any file with the latter name and would treat the shared one as a competing root configuration.

Relative imports carry explicit .ts extensions. That is what lets the Node test runner execute the TypeScript sources directly, without a build step or a loader.
