Deployment

One Node process serving both the API and the frontend.

Read this first

You are deploying remote shell access. Work through Security before it is reachable from anywhere but loopback.

The build output

pnpm install
pnpm build

apps/server/dist/ then contains everything needed to run:

dist/
├── main.js          the bundled server
├── main.js.map
├── package.json     one dependency: node-pty
└── public/          the built frontend

Copy that directory to the host and install the one native dependency:

scp -r apps/server/dist websh.example.com:/opt/node-websh
ssh websh.example.com 'cd /opt/node-websh && npm install --omit=dev'

node-pty ships prebuilt binaries for common platforms, so this normally downloads rather than compiles. If it does have to build, the host needs a C++ toolchain and Python.

Running it as a service

A dedicated unprivileged user, a fixed token, and loopback only — with TLS terminated by a proxy in front. 

sudo useradd --system --create-home --shell /bin/bash websh
sudo install -d -o websh -g websh /etc/websh
printf 'WEBSH_TOKEN=%s\n' "$(openssl rand -hex 24)" | sudo tee /etc/websh/env >/dev/null
sudo chmod 600 /etc/websh/env
sudo chown websh:websh /etc/websh/env

/etc/systemd/system/websh.service:

[Unit]
Description=node-websh terminal server
After=network.target

[Service]
User=websh
WorkingDirectory=/opt/node-websh
EnvironmentFile=/etc/websh/env
Environment=WEBSH_HOST=127.0.0.1
Environment=WEBSH_PORT=8999
Environment=WEBSH_SECURE_COOKIE=1
ExecStart=/usr/bin/node /opt/node-websh/main.js
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now websh
sudo systemctl status websh
Restarts end sessions

Sessions are held in memory, so everyone signs in again after a restart. Shells are killed too — they are children of the server process.

Locale

systemd units start with no LANG or LC_*. The server sets a UTF-8 locale on the child itself, so this is handled — but if you override LC_CTYPE to something non-UTF-8 in the unit file, typing non-ASCII in the terminal will break.

Reverse proxy

The proxy must forward WebSocket upgrades and pass X-Forwarded-Proto, which is how the server decides to mark the session cookie Secure.

Caddy

websh.example.com {
    reverse_proxy 127.0.0.1:8999
}

Caddy handles certificates, upgrades and forwarded headers with no further configuration.

nginx

server {
    listen 443 ssl http2;
    server_name websh.example.com;

    ssl_certificate     /etc/letsencrypt/live/websh.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/websh.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8999;
        proxy_http_version 1.1;

        # Without these two the WebSocket upgrade fails and the terminal
        # never connects.
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For   $remote_addr;

        # A terminal can idle for a long time between keystrokes.
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
Keep the Host header intact

The origin check compares the request's Origin against its Host. A proxy that rewrites Host to 127.0.0.1:8999 will make every browser connection look cross-origin and get closed with 4001. Either preserve Host, or list the public origin in WEBSH_ALLOWED_ORIGINS.

Docker

FROM node:22-bookworm-slim AS build
WORKDIR /src
RUN corepack enable
COPY . .
RUN pnpm install --frozen-lockfile && pnpm build

FROM node:22-bookworm-slim
RUN useradd --create-home --shell /bin/bash websh
WORKDIR /app
COPY --from=build /src/apps/server/dist ./
RUN npm install --omit=dev && chown -R websh:websh /app

USER websh
ENV WEBSH_HOST=0.0.0.0 WEBSH_PORT=8999 WEBSH_SHELL=/bin/bash
EXPOSE 8999
CMD ["node", "main.js"]
docker run --rm -p 8999:8999 -e WEBSH_TOKEN="$(openssl rand -hex 24)" node-websh

WEBSH_HOST=0.0.0.0 is correct inside a container — the container boundary is what limits reachability. Publish the port only where you intend it to be reachable.

Checking it works

curl -s https://websh.example.com/api/info
{"version":"0.2.0","protocolVersion":1,"authRequired":true}

authRequired: false here means the server is running with --insecure-no-auth and anyone who can reach it has a shell.

When something is wrong

Symptom Likely cause
Login works, terminal stays "Reconnecting…" The proxy is not forwarding the WebSocket upgrade.
Immediately bounced back to the login screen Origin check failing (rewritten Host), or a Secure cookie set on a connection the browser sees as plain HTTP.
posix_spawnp failed on every connection node-pty's spawn-helper lost its executable bit. Re-run node scripts/postinstall.mjs, or chmod +x it under node_modules.
Connection drops after a few minutes idle Proxy read timeout too low.
The page loads but shows no terminal The frontend was not built, or public/ was not copied next to main.js. The startup banner says so.
